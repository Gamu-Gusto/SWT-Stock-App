# Test deployment on Render

Render runs the app from the included `Dockerfile` (PHP 8.3 + Apache) with a managed PostgreSQL database,
both defined in [`render.yaml`](../render.yaml). It is meant for **testing and demonstrations**. Live trading
should use the DirectAdmin deployment ([DEPLOYMENT_DIRECTADMIN.md](DEPLOYMENT_DIRECTADMIN.md)) or paid Render
plans with backups and a persistent disk.

## What the free plan means

| Limitation | Effect on testing |
|---|---|
| Web service sleeps after 15 minutes without visits | First visit afterwards takes about a minute to wake up. |
| Disk is wiped on every restart/redeploy | Uploaded tyre photos, delivery-note attachments, an uploaded replacement logo and pending import files disappear. Stock, sales and everything in the database are kept. The built-in logo is unaffected. |
| Free PostgreSQL: 1 GB, no backups, deleted 30 days after creation | Do not enter real business data you need to keep. |
| No shell access | Owner account is created through the one-time `/setup` page instead of `php artisan`. |
| Region | Frankfurt is the closest Render region to South Africa (~160 ms per request). |

## Deploy

1. Push the repository to GitHub (already connected).
2. Render Dashboard → **New → Blueprint** → choose `Gamu-Gusto/SWT-Stock-App` → branch `main`.
   Render reads `render.yaml` and shows two resources: **swt-stock** (web) and **swt-stock-db** (PostgreSQL). Click **Apply**.
3. Wait for the first build (5–10 minutes: frontend build, PHP extensions, Composer). The start-up log shows the
   database migrations running. When the service is *Live*, note its address, e.g. `https://swt-stock.onrender.com`.
4. Open **swt-stock → Environment**, reveal and copy **SETUP_TOKEN**.
5. Open `https://<your-address>/setup`, paste the token, enter the owner's name, e-mail and password (10+ characters,
   letters and numbers) and submit. You are taken to the sign-in page. The setup page locks itself permanently once an
   owner exists (you may also delete `SETUP_TOKEN` in the Environment tab afterwards).
6. Sign in and continue with the normal first-day steps in [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

### Optional: demo data

To try the system with **fictional** tyres, sales and reservations, set `LOAD_DEMO_DATA=true` in the Environment tab
and redeploy. It also creates demo accounts (`owner@demo.test`, `manager@demo.test`, `sales@demo.test`, … with the
password published in the source code), so only do this while the address is private, and set it back to `false`
afterwards. It never runs when `APP_ENV=production`.

## Updating

Every push to `main` triggers an automatic redeploy (`autoDeployTrigger: commit`). Migrations run on start-up.
GitHub Actions (`.github/workflows/tests.yml`) runs the full test suite on SQLite, MySQL and PostgreSQL and checks
that the Docker image builds and serves pages – check that it is green before relying on a deploy.

## Configuration reference (render.yaml)

| Variable | Value | Why |
|---|---|---|
| `APP_ENV` | `staging` | Test deployment (`production` blocks demo data). |
| `APP_KEY`, `SETUP_TOKEN` | generated by Render | Secret; the start script adds Laravel's `base64:` prefix to the key. |
| `DB_CONNECTION` / `DB_URL` | `pgsql` / internal connection string | Database is reachable only from Render (`ipAllowList: []`). |
| `SESSION_SECURE_COOKIE`, `TRUSTED_PROXIES` | `true`, `*` | Render terminates HTTPS in front of the container. |
| `LOG_CHANNEL` | `stderr` | Errors appear under the service's **Logs** tab. |
| `MAIL_MAILER` | `log` | E-mail off; add SMTP variables (see `.env.example`) to send password-reset links and alerts. |

`APP_URL` is taken automatically from Render's `RENDER_EXTERNAL_URL`.

## Custom domain (optional)

Service → **Settings → Custom Domains** → add e.g. `stock-test.superwheeltyres.co.za` and create the CNAME record Render
shows at your DNS provider. This does not affect the main website.

## Moving from test to live

Render free resources are not suitable for the business's real stock records. For live use either deploy to DirectAdmin
(recommended, MySQL) or upgrade on Render: a paid Postgres plan (backups), a paid web service with a persistent disk
mounted at `/var/www/html/storage/app/private` for uploads, and `APP_ENV=production`.

## Database support

The application runs on MySQL 8 / MariaDB 10.6+ (DirectAdmin) and PostgreSQL 15+ (Render). Text searches are
case-insensitive on both; stock invariants (no negative stock, reserved ≤ on hand) are enforced by database CHECK
constraints on MySQL and PostgreSQL in addition to the application.
